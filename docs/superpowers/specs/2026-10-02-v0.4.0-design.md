## 3. 메모리 다이어트

### 3.1 Window Registry 패턴

`src/main/window-registry.ts` (신규):

```ts
let memoWin: BrowserWindow | null = null;

export function ensureMemoWindow(): BrowserWindow {
  if (memoWin && !memoWin.isDestroyed()) return memoWin;
  memoWin = createMemoWindow();
  memoWin.on("closed", () => { memoWin = null; });
  if (process.env.ELECTRON_RENDERER_URL) {
    memoWin.loadURL(`${process.env.ELECTRON_RENDERER_URL}/memo/index.html`);
  } else {
    memoWin.loadFile(join(__dirname, "../renderer/memo/index.html"));
  }
  return memoWin;
}
// launcher/settings/info 동일 패턴
```

### 3.2 창 close 로직 변경

**현재** (memo/launcher/settings/info 공통):
```ts
win.on("close", (e) => { e.preventDefault(); win.hide(); });
```

**변경 후**:
- `preventDefault` 제거 → 자연스럽게 destroy
- `closed` 이벤트에서 참조 해제 (`memoWin = null;`)

### 3.3 진입 지점 전환

| 진입 지점 | 현재 | 변경 후 |
|---|---|---|
| 트레이 "설정" | `settingsWin.show()` | `ensureSettingsWindow().show()` |
| 트레이 "도움말" | `showInfoWindow("help")` | `ensureInfoWindow()` + show + IPC(section) |
| 트레이 "뽁이에 대해" | `showInfoWindow("about")` | 동일 |
| bubble "memo" 선택 | `memoWin.show()` | `ensureMemoWindow().show()` |
| bubble "launcher" 선택 | `launcherWin.show()` | `ensureLauncherWindow().show()` |
| `Ctrl+Alt+M` 단축키 | `memoWin.show()` | `ensureMemoWindow().show()` |
| First-run 자동 도움말 | `showInfoWindow("help")` | 동일 (ensure 포함) |

### 3.4 토스트 안전

- `memos:add` 등 핸들러에서 `pet:toast`로 메시지 보내는데 pet 창은 상주이므로 안전
- 메모 창이 destroyed라도 데이터는 Store(JSON)에 저장되어 손실 없음

### 3.5 Edge cases

- **생성 중 재진입**: ensure → 창 생성 시작 → 로딩 중 다시 ensure. 두 번째 호출은 같은 참조 반환. `show()` 멱등.
- **destroy 직후 재진입**: `closed` 이벤트에서 참조 null. 다음 ensure는 새 창 생성.
- **shutdown 중 ensure 호출**: `isShuttingDown` 가드로 ensure가 null 반환하거나 skip.

### 3.6 예상 수치

| 상태 | 현재 (v0.3.0) | v0.4.0 | 절감 |
|---|---|---|---|
| 상시 (0 창 열림) | 757 MB | ~250 MB | **-67%** |
| 메모만 열어둠 | 757 MB | ~340 MB | -55% |
| 6개 창 다 열림 | 757 MB | ~760 MB | ~0% (의도) |
| 다 열었다 다 닫음 | 757 MB | ~250 MB | **-67%** |

## 4. 포모도로

### 4.1 상태 머신

```
idle  ──start──▶  focus  ──focusMs 종료──▶  break
                   ▲                        │
                   │                        │
                   │                     breakMs 종료
                   │                        │
                   └── stop ◀── idle ◀──────┘
```

- `idle`: 타이머 없음, 배지 숨김
- `focus`: 집중 (기본 25분), 뽁이 sit 고정
- `break`: 휴식 (기본 5분), 뽁이 happy + walk 자유

**자동**: focus → break
**수동**: idle → focus (유저가 트레이 "포모도로 시작" 클릭)
**수동 중지**: focus/break → idle (유저가 "포모도로 중지")
**break 종료 후**: idle로 복귀, 재시작은 수동

### 4.2 PomodoroController 인터페이스

```ts
// src/main/pomodoro-controller.ts
export type Phase = "idle" | "focus" | "break";

export class PomodoroController {
  constructor(opts: { focusMs: number; breakMs: number; now?: () => number });

  readonly phase: Phase;
  readonly remainingMs: number;

  start(): void;
  stop(): void;
  tick(nowMs: number): void;
  updateDurations(focusMs: number, breakMs: number): void;

  onPhaseChange(cb: (phase: Phase, remainingMs: number) => void): void;
}
```

**규칙**:
- `start()` 중 어떤 phase든 호출 → idle이면 focus 시작, focus/break면 무시 (멱등)
- `stop()` → 어떤 phase든 idle
- `tick(now)` → 현재 phase 남은 시간 계산. 종료 시 자동 전환.
- `updateDurations` → 현재 세션은 유지, 다음 세션부터 반영.
- `onPhaseChange` 콜백은 **전환 시점에만** 1회 발화 (매 tick마다 X).

### 4.3 PetController와의 lock 연동

PetController에 추가:
```ts
private focusLock = false;

setFocusLock(locked: boolean): void {
  this.focusLock = locked;
  if (locked) this.enter("sit");
}

// enter() 로직 수정:
// - focusLock=true 상태에서 happy/fall 종료 → sit으로 복귀 (기존 idle 대신)
// - focusLock=true면 rollIdleBranch에서 walk/sit 선택 안 함 (sit 유지)
```

Main에서:
- `pomodoro.onPhaseChange("focus", _)` → `petController.setFocusLock(true)`
- `pomodoro.onPhaseChange("break", _)` → `petController.setFocusLock(false)`
- `pomodoro.onPhaseChange("idle", _)` → `petController.setFocusLock(false)`

**집중 중 유저 click**: happy 1200ms → 자동 sit 복귀 (lock 유지). 유저와의 소통은 가능, 산만한 walk/sleep은 차단.

### 4.5 트레이 메뉴 통합

```
🐩 뽁이 트레이 메뉴
├── 숨기기/보이기
├── ⏱ 포모도로 시작                      ← phase === idle
│   또는 ⏱ 포모도로 중지 (집중 23:45)    ← phase === focus
│   또는 ⏱ 포모도로 중지 (휴식 4:12)     ← phase === break
├── 설정
├── 도움말
├── 업데이트 확인
├── 뽁이에 대해…
├── ────
└── 종료
```

**메뉴 rebuild 전략**: 메뉴는 유저가 클릭한 순간에만 표시되므로, 매번 rebuild. Electron Tray는 `right-click`과 `click`(좌클릭) 둘 다 이벤트 발화:

```ts
function openMenu() {
  tray.popUpContextMenu(buildMenu(controller.phase, controller.remainingMs));
}
tray.on("right-click", openMenu);
tray.on("click", openMenu);
```

(Windows 트레이에서 좌/우 모두 메뉴 띄우는 기존 뽁이 패턴 유지)

### 4.6 토스트 알림

| 전환 | 토스트 메시지 |
|---|---|
| idle → focus (수동 start) | 없음 |
| focus → break (자동) | "집중 끝! 5분 쉬어요 🍵" |
| break → idle (자동 종료) | "다시 집중할까요? ☕" |
| any → idle (수동 stop) | 없음 |

기존 `pet:toast` IPC 재활용. 2000ms 표시.

### 4.7 Tick 주기

- `setInterval(1000)` main process → `pomodoro.tick(performance.now())` 호출
- phase가 focus/break일 때 매 tick마다 `pet:pomoBadge({ phase, remainingSec })` IPC 발송
- 1초 간격 IPC 1개는 가볍움 (pet 이동 tick이 33ms인 것 대비)
- phase가 idle되면 `pet:pomoHide` IPC 1회

## 5. 데이터·IPC

### 5.1 Settings 타입 확장

```ts
// src/shared/types.ts
export type Settings = {
  // 기존
  spriteScale: number;
  walkSpeedPxPerSec: number;
  shortcutQuickMemo: string;
  hideOnFullscreen: boolean;
  autoStart: boolean;
  // 신규
  pomodoroFocusMin: number;    // 15~60, 기본 25
  pomodoroBreakMin: number;    // 3~15, 기본 5
};

export const DEFAULT_SETTINGS: Settings = {
  ...,
  pomodoroFocusMin: 25,
  pomodoroBreakMin: 5
};
```

영속화: 기존 `settingsStore` 그대로. `settings.json`에 자동 저장.

### 5.2 IPC 채널

| 채널 | 방향 | 페이로드 | 호출 시점 |
|---|---|---|---|
| `pet:pomoBadge` | main → pet | `{ phase: Phase, remainingSec: number }` | 1초마다 (focus/break) + phase 전환 즉시 |
| `pet:pomoHide` | main → pet | (없음) | phase가 idle이 될 때 |
| `pet:toast` | main → pet | `{ text, ms }` | **기존 재활용** — 전환 알림 |
| `settings:update` | renderer → main | `Partial<Settings>` | **기존 재활용** — pomodoro 분 변경 포함 |
| `settings:get` | renderer → main | → `Settings` | **기존 재활용** |

**트레이 → controller는 IPC 아님** — tray는 main process 내부, 직접 호출.

### 5.3 Preload API 추가

```ts
// src/preload/index.ts
const pet = {
  // 기존
  getSprite, onState, onFacing, onToast, onRescale, action, dragMove,
  openBubble, chooseAction, dropFiles,
  // 신규
  onPomoBadge: (cb: (p: { phase: "idle"|"focus"|"break", remainingSec: number }) => void) =>
    ipcRenderer.on("pet:pomoBadge", (_, p) => cb(p)),
  onPomoHide: (cb: () => void) => ipcRenderer.on("pet:pomoHide", () => cb())
};
```

`settings` API는 타입만 확장, 메서드 추가 없음.

### 5.4 세션 상태 영속화

**없음**. PomodoroController의 phase·remainingMs는 메모리 only. 앱 재시작 시 idle로 초기화. 25분 세션이라 복구할 가치 없음.

## 6. 테스트·오류 처리·성능 측정

### 6.1 유닛 테스트

`tests/unit/pomodoro-controller.test.ts` (약 10 테스트):

- starts in idle
- `start()` → focus, remaining = focusMs
- tick after focusMs in focus → auto-transition to break
- tick after breakMs in break → auto-transition to idle (수동 재시작)
- `stop()` during focus → idle
- `stop()` during break → idle
- `start()` during focus/break → 무시 (멱등)
- `updateDurations` during idle → 다음 start부터 반영
- `updateDurations` during focus → current session 유지
- `onPhaseChange` 전환 시에만 fire (tick마다 X)
- `remainingMs` ≥ 0 clamp

`window-registry` 유닛 테스트는 생략 (BrowserWindow 모킹 복잡, e2e로 커버).

### 6.2 E2E 스모크 추가

`tests/e2e/smoke.spec.ts`에 2개 추가:

- **메모 창 lazy**: 초기 창 수 ≤ 2 → bubble memo 선택 → 메모 창 생성 확인 → 닫음 → 참조 null 확인
- **포모도로 start → focus 배지 표시**: controller 직접 호출 → pet renderer `#pomo-badge` 가 `.focus` 클래스 가짐

### 6.3 메모리 측정 스크립트

`scripts/measure-memory.mjs`:

- Playwright Electron 실행
- 5개 시나리오 setup → 2초 안정화 → `Get-Process`(또는 node ps-list)로 WorkingSet 합계
- 시나리오: 초기 / 메모만 / 메모+런처 / 6개 다 / 다 열었다 다 닫음
- 표 형태 출력

실행은 수동 (`npm run measure:memory`). CI 통합 X. v0.4.0 머지 전 1회 측정 → 블로그 공개.

### 6.4 오류 처리

| 상황 | 처리 |
|---|---|
| `ensureXxxWindow` 중 생성 실패 | throw → 호출자 catch → 트레이 balloon "창 열기 실패" |
| tray rebuild 중 tray destroyed | `tray.isDestroyed()` 가드 |
| pomodoro tick 중 shutdown 시작 | `isShuttingDown` 가드 → tick skip |
| focus lock 중 "💤 재우기" 선택 | 토스트 "포모도로 중이에요 🙂 중지 후 재우기", sleep 진입 안 함 |
| phase 전환 시 pet 창 destroyed | 기존 `petWindowAlive()` 가드 활용 |
| 설정 변경 시 current session 영향 | current session 유지, 다음부터 반영 (유저 안내 토스트) |

### 6.5 성능 회귀 감지

- 상시 메모리 목표: ≤ 300 MB
- 미달 시 조치 후보: `webContents.setBackgroundThrottling(true)`, `nodeIntegrationInWorker: false` 확인, GPU process 확인
